# AI 활용 기록

이 문서는 게임 제작 과정에서 사용한 AI 도구, 프롬프트, 채택 결과 및 사람의 수정 판단을 기록합니다.

## 2026-08-06 — 콘셉트 및 개발 환경

- 사용 도구: OpenAI Codex
- 목적: 사전과제 조건 분석, 게임 콘셉트 구체화, 웹 기술 스택 선정 및 초기 프로젝트 구성
- 주요 지시 사항:
  - 브라우저에서 즉시 실행 가능한 게임으로 제작
  - 플레이어와 적 모두 한 발에 사망
  - 조준 중 시간 정지 및 도탄 예상선 표시
  - 발사 후 비무장 상태로 총알 직접 회수
  - GitHub Pages에 배포 가능한 정적 빌드 구성
- AI 제안 중 채택:
  - Vite + TypeScript + Phaser 구성
  - 총알이 플레이어에게도 피해를 주는 규칙
  - 반사벽·흡수벽·유리벽으로 장애물 역할 구분
- 사람의 최종 결정:
  - 모바일 앱 대신 웹 게임으로 제출
  - 런타임 생성형 AI나 외부 API는 사용하지 않음
  - AI는 제작·코딩·검토 과정에 활용하고 기록을 공개
  - 최신 시험판 조합 대신 Phaser 3.90.0, Vite 7.3.5, TypeScript 5.9.3으로 버전을 고정
  - Windows 개발 서버는 외부에 노출하지 않고 `127.0.0.1`에만 바인딩

> 이후 AI를 사용할 때마다 날짜, 도구, 프롬프트 요약, 생성 결과, 채택 여부와 수정 이유를 추가합니다.

## 2026-08-06 — 플레이 완성도 및 구조 개선

- 사용 도구: OpenAI Codex
- 목적: 프로토타입을 5개 구역으로 확장하고 충돌 안정성, 연출, 유지보수 구조 보완
- 주요 지시 사항:
  - 플레이 편의 기능을 제외한 기술·콘텐츠·연출·제출 준비 항목 수정
  - 조준 오버레이와 입력 이탈 문제 수정
  - 빠른 탄환이 대상을 통과하지 않도록 연속 충돌 판정 적용
  - 스테이지 5개와 보스 1종 구현
  - 외부 에셋 없이 효과음과 파티클 생성
- AI 제안 중 채택:
  - 선분-원 교차 기반 탄환 충돌과 회귀 테스트
  - 데이터 기반 스테이지 정의
  - Web Audio API 기반 합성 효과음
  - 게임 상수, 타입, 스테이지, 충돌, 사운드 모듈 분리
- 사람의 최종 결정:
  - 기존의 한 발 즉사 규칙은 일반 적에게 유지
  - 최종 보스만 3중 보호막을 사용해 캠페인 종착점으로 차별화
  - 모바일 조작, 설정, 기록 저장 등 플레이 편의 기능은 이번 변경 범위에서 제외

## 2026-08-07 — 최신 픽셀 화면과 로컬 개선 작업 병합

- 사용 도구: OpenAI Codex
- 목적: 원격 저장소의 코드 생성 픽셀 화면에 로컬의 5개 스테이지, 연속 충돌, 효과음, 모듈 구조 적용
- 적용 내용:
  - 16×16 플레이어·일반 적·탄환 텍스처와 픽셀 던전 팔레트 유지
  - 36×40 크기의 전용 보스 텍스처를 새로 구성하고 일반 적보다 약 3~4배 크게 렌더링
  - 보스 중앙 자수정 코어, 보호막 결정, 보라색 그림자와 3단계 보호막 HUD 추가
  - 선분 기반 탄환 충돌, 파티클, 화면 흔들림, Web Audio 효과음과 5개 스테이지 병합
  - 개발 환경에서 `?stage=5` 주소로 보스 스테이지를 직접 검증할 수 있도록 구성
- 검증:
  - 충돌 단위 테스트 4개 통과
  - TypeScript 및 Vite 프로덕션 빌드 통과
  - 로컬 브라우저에서 1스테이지와 보스 스테이지 렌더링 및 콘솔 오류 확인
